Write a program that works on Windows and Mac:
1. Rust or C++ client (Speed is key) (compiled to .exe, with interface, startup with system, reference the Windows install and trays in ~/GolandProjects/ToolboxApps, ~/GolandProjects/Sparkle (don't modify these reference projects)). Mac is similar.
2. clients run on individual PCs with a config file, clients connect to each other (auto discover on LAN, a lot of other devices on LAN, be careful)
3. Each client has the ability to capture its own PC audio and become master with a virtual audio output device created by this client, make sure the virtual audio device doesn't break any Windows settings, research online on similar projects or libraries, and is low-latency when captured by this project
3. Audio capture: Any client can claim to be master. The master's audio is captured as is (no distortion, no post-processing, if the virtual audio device is configured as multi-channel, the audio is captured in multi-channel)
4. Audio playing on master: The audio gets played on the master nodes with another configured output device through the client, the output device usually has the same speaker layout as the virtual output device (user will configure), if not, log warnings and prompt user
5. Audio syncing on all nodes: All nodes receive the audio broadcast by all master nodes in extremely low latency, the audio should be lossless and contain multi-channel info. The receiving clients play the audio directly through the current output device (should have the same speaker layout as the master node, if not, warn and prompt user).
6. The tricky part: We program the app to be extreme low latency, but the speakers on different PCs (laptop speakers, TV speakers, TV E-ARC, and Bluetooth speakers) have different latency levels, and it's possible that the master node can have the highest latency. We need to add an adaptive perfect delay so all speakers stay in sync across devices. There can be an auto or manual calibration process, using external microphones to sync, or even simply add/remove delays on each node, etc. Ideally, the way to sync should be simple (not too over-engineered) but very effective. Ask with options if you have a proposal.
7. To reduce the complexity for now, Mac can only be a slave node (listening to other master audio and stream from them), don't listen on Mac nodes.

The end goal is to have all clients play audio in sync, streamed from the master node, in the same environment, with multi-channel support on Windows and Mac.

Note as multiple nodes can become masters, this means we can just have all nodes play audio from all nodes

Assumptions: All clients on LAN with ethernet connections, bandwidth is ample (at least 1Gbps)

Feel free to test on this Windows PC, avoid touching unnecessary resources and don't break anything

Ask as long as there are blockers or if you have questions.
